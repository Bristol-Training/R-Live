# Introduction to R and Data Analysis (combined course)

A single live-coding course combining the JGI's *Intro to R (Part 1)*, *Intro to R (Part 2)* and *Introduction to Data Analysis in R*. All examples use the Palmer penguins data from the [`palmerpenguins`](https://allisonhorst.github.io/palmerpenguins/) package.

This course is written with [Quarto](https://quarto.org).

## What's in this folder

```
R-Course-Live/
├── README.md
├── render.R          renders everything in one go (see below)
├── DESCRIPTION       R packages the course needs
├── source/           what you edit
│   ├── r-course-notes.qmd    the course notes (one document covering every topic)
│   ├── r-course-slides.qmd   the revealjs slides for the live-coding session
│   ├── styles.scss           notes styling (same as the existing JGI courses)
│   ├── slides.scss           slide theme (JGI purple)
│   └── assets/               logo and images
├── resources/        the rendered course pages (generated by render.R)
└── docs/             the course website for GitHub Pages (generated by render.R)
```

Don't edit anything in `resources/` or `docs/` by hand: `render.R` overwrites it.

## Which output goes to whom

| Output | Audience | Contains |
|---|---|---|
| `docs/` (the website) | **Everyone** (the one link to send out) | Attendee notes with the slides embedded at the top, plus links to the instructor version and the longer-form courses |
| `resources/r-course-notes.html` | **Delivery team** | Full notes **plus** red *Instructor notes* boxes (timings, live-coding cues, common pitfalls) |
| `resources/r-course-slides.html` | **Delivery team** (presented on screen) | Overview slides for each section |
| `resources/r-course-notes-attendee.html` | **Attendees** (if you need to email a copy) | Full notes with all instructor notes removed |

Every page is a single, self-contained HTML file (images and styles are embedded), so any of them can be emailed or uploaded to a VLE as it is.

## Setup

Install Quarto from <https://quarto.org/docs/get-started/>, then install the R packages:

```r
install.packages(c("tidyverse", "palmerpenguins", "lme4", "rpart",
                   "quarto", "knitr", "rmarkdown"))
```

## Rendering

### Everything at once (recommended)

From the top-level folder, run:

```bash
Rscript render.R
```

or open `render.R` in RStudio, set the working directory to the top-level folder (*Session → Set Working Directory → To Source File Location*) and click **Source**.

This creates the course pages in `resources/` and the website in `docs/`, and checks that the attendee versions contain no instructor notes.

### One output at a time

From a terminal in the `source/` folder (these write the HTML next to the `.qmd`, which git ignores; use `render.R` to update `resources/` and `docs/`):

```bash
# Instructor notes
quarto render r-course-notes.qmd

# Attendee notes
quarto render r-course-notes.qmd -M attendee:true --output r-course-notes-attendee.html

# Slides
quarto render r-course-slides.qmd
```

### Live preview while editing

From the `source/` folder:

```bash
quarto preview r-course-notes.qmd     # instructor view
quarto preview r-course-slides.qmd
```

The preview refreshes in your browser each time you save. (In RStudio you can also use the **Render** button on an open `.qmd` file, which produces the instructor version.)

## Publishing the website (GitHub Pages)

`render.R` builds the website into `docs/`:

| File | What it is |
|---|---|
| `docs/index.html` | The landing page: a short intro, the embedded slides, links to materials, then the attendee notes |
| `docs/slides.html` | Copy of `resources/r-course-slides.html` (embedded on the landing page and opened full screen from it) |
| `docs/instructor.html` | Copy of `resources/r-course-notes.html` |

The landing-page block lives at the top of `source/r-course-notes.qmd`, inside `::: {.content-visible when-meta="site"}`, so it only appears in the website build. The links to the longer-form courses are marked `TODO` there.

To publish:

1. Run `Rscript render.R`.
2. Commit and push, including the `docs/` folder.
3. One-time setup on GitHub: **Settings → Pages → Build and deployment → Deploy from a branch**, then pick `main` and `/docs`.

The site appears at `https://<user-or-org>.github.io/<repo>/` a minute or two after each push. GitHub Pages sites are public, so anyone with the link can read the instructor version too.

## Editing the notes

The notes follow the house style of the existing JGI courses:

```markdown
::: {#exerciseN .callout-note icon=false title='Exercise'}
The exercise (one at the end of each section).
:::

::: {#answerN .callout-caution icon=false title='Answer' collapse="true"}
The answer (collapsed by default).
:::

::: {#keypointsN .callout-tip icon=false title='Key points'}
Important concepts.
:::
```

### Adding instructor-only content

Wrap anything that attendees should **not** see in a `content-hidden` block. It shows in the instructor version and is removed from the attendee version:

```markdown
::: {.content-hidden when-meta="attendee"}
::: {.callout-important icon=false title='Instructor notes'}
**Live code:** ...

**Pitfalls:** ...
:::
:::
```

Keep the title `Instructor notes`: `render.R` searches for it to check that nothing has leaked into the attendee copy.

### Deliberate errors

Code chunks that demonstrate an error on purpose are marked `#| purl: false`. This keeps them out of a script extracted with `knitr::purl("r-course-notes.qmd")`, so the extracted script runs from top to bottom. `knitr::purl()` is a handy way to produce a complete "solutions" script.
